# 12 Links Team Code of Conduct

## Overview
This document outlines the expectations for collaboration, code quality, and professional behavior for all developers and contributors working on the Chuse App and within the 12 Links repository.

## Professionalism and Collaboration
* **Constructive Code Reviews:** Review code, not the developer. Provide actionable, polite feedback. When your code is reviewed, assume positive intent and be open to suggestions.
* **Respectful Communication:** Maintain a professional and respectful tone in all pull requests, issue trackers, and team communications.
* **Accountability:** Own your code. If you introduce a bug, work collaboratively to fix it rather than assigning blame.

## Security and Confidentiality
* **Proprietary Property:** All code, documentation, and assets within this repository are the sole, confidential property of 12 Links.
* **No Unauthorized Sharing:** Do not share, copy, or discuss the internal workings of the Chuse App codebase outside of authorized 12 Links channels.
* **Secret Management:** NEVER commit API keys, passwords, or `.env` files. If a secret is accidentally exposed, report it to the technical lead immediately so it can be rotated.

## Code Quality Standards
* **Test Before Pushing:** Ensure your code compiles and passes all local tests before opening a Pull Request.
* **Documentation:** Leave the codebase better than you found it. Comment complex logic and keep the README up to date.

## Reporting Issues
If you experience friction in the development process, suspect a security breach, or encounter unprofessional behavior, please escalate the issue directly to management at info@12links.co.za.
